# Ý tưởng Feature Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox syntax for tracking.

**Goal:** Ship user-owned idea creation, list, and detail pages in Smart Idea.

**Architecture:** Add Drizzle tables for ideas and per-idea revenue labels. Keep data access in a server-only idea repository, create through a server action that derives the owner from the authenticated session, and render list/detail routes as server components inside the existing workspace auth guard.

**Tech Stack:** Next.js App Router, React, TypeScript, Drizzle ORM, PostgreSQL, pnpm.

**Spec:** docs/superpowers/specs/2026-10-11-ideas-design.md

## Global Constraints

- All idea access is scoped by the current app_users.id.
- industry and revenue model names remain free-form text; revenue models are multiple labels per idea.
- Keep routes under the authenticated workspace layout.
- Preserve Vietnamese copy and existing navy/coral styles.
- Before writing route or server-action code, read the relevant Next.js 16 guides under apps/web/node_modules/next/dist/docs as required by apps/web/AGENTS.md.
- Do not add or run tests; validate with build, lint, typecheck, and diff checks.

## Review Focus

- Cross-user access: detail lookup must include both idea ID and owner ID; a foreign ID returns not-found.
- Forged owner: create action must ignore any submitted user ID and derive it from the session.
- Empty or whitespace-only name: reject after trimming and show a useful form error.
- Revenue label input: trim, skip empty lines, and deduplicate case-insensitively without losing the first label's display casing.
- Empty and populated lists: render a create CTA when empty and links to each detail when populated.
